# 問題ファイルの書き方

問題は 1 問 1 ファイルの Markdown でここに置く。ファイル名は `<難易度>_<番号>_<短い題名>.md`。
難易度の接頭辞は `s1` (一ツ星) / `s2` (二ツ星) / `s3` (三ツ星) / `q` (おまめ専用、既存の 10 問)。
追加・修正したら Claude に「docs/question を実装に反映して」と依頼する。Claude が内容を読んで
`src/data/` の TypeScript データと、必要なら新しい形式の UI を実装する。自動パーサはない。

## 難易度の定義 (2026-09-13 決定)

| 難易度 | 問う知識 | 使う形式 | 例 |
|---|---|---|---|
| 一ツ星 | アニメ・原作を一通り見た人なら分かる。主要キャラ、主要な出来事、念の基本 | マルバツ / 4択 | ゴンの父の名前は? |
| 二ツ星 | 各編の細部。サブキャラの名前、能力名、出来事の順序 | + 並べ替え / 仕分け | 試験官を担当順に並べる |
| 三ツ星 | 設定の細部。数値、ルールの細かい条件、セリフ、巻数 | 全形式 | ハコワレの利息は 10 秒ごとに何 %? |
| おまめ専用 | 応用・複合。1 問に複数の事実を含み、難易度は三ツ星以上。単純なマルバツは 10 問中 1〜2 問まで | 全形式 | q01〜q20 |

各難易度 20 問以上を目標にする (1 プレイ 10 問をランダム抽出するため)。

## 問題作成のルール

1. **出典を必ず書く。** `## 根拠` に参照した資料を書く。優先順は (1) 原作単行本の巻数、(2) Wikipedia 日本語版の該当項目、(3) 公式ファンブック等。出典が書けない事実は出題しない。
2. **確信度を付ける。** `## 根拠` の末尾に ★★★ (出典本文に明記されている) / ★★☆ (出典と記憶の組み合わせ、または解釈を含む) を付ける。★★☆ の問題は `## 実装メモ` に「原作で確認推奨」と書き、公開前に作成者 (人間) が原作で確認する。
3. **Claude が草案を作る場合**は、Claude 自身の記憶に基づく草案であり、上記の出典を実際に参照したわけではない。必ず作成者が確認してから公開する。特に数値・回数・巻数・順序は誤りやすいので ★★☆ 扱いにする。
4. **正誤が確定している事実だけを出題する。** 連載中で変わりうる情報、ファンの解釈が分かれる事柄、作中で明言されていない推測は出題しない。
5. **原作の画像や長い本文引用は使わない。** セリフを問う場合も短い引用にとどめる。
6. **問題文は丁寧語で書く** (「選んでください」「並べてください」)。命令形 (「選べ」「埋めよ」) は使わない。
7. **誤答 (ダミー) の作り方。** 4択は正解と同じカテゴリ (人物なら人物、数値なら近い数値) から選ぶ。作中に存在しない名前を混ぜるのは 1 つまで。仕分け・組み合わせは、余りの候補も作中に実在するものにする。
8. **組み合わせ問題は候補が単一使用**なので、正解が行ごとに異なるように作る。同じ候補を 2 行で使う問題は不可。
9. **仕分け問題は箱の名前を明示し、正解の数は示さない。** 「誤っているものを選べ」ではなく「誤っている / 正しい に仕分けてください」の形にする。
10. **難易度に合った形式を使う。** 一ツ星はマルバツ・4択のみ。二ツ星以上で並べ替え・仕分け、三ツ星以上で穴埋め・組み合わせを使う。
11. **誤り箇所を選ぶ問題 (本文の破線部 (a)〜 から誤りを選ぶ 4択) は、選択肢の末尾に「すべて誤り」「誤りはない」を必ず加える。** 消去法や「必ず 1 つは誤り」という前提を崩すため。選択肢は並べ替えない。
12. **他の問題と正解が重複しないようにする。** 同じ事実を別の難易度で問わない (例: ナニカのおねだり回数はおまめ専用で出題済み)。

## 動作確認

`npm run dev` で起動し、`http://localhost:5173/h_h_quiz/?q=om09` のように問題の id を付けると、その 1 問だけを出題する。

## テンプレート

```markdown
# Q1. <形式>｜<題名>

- 難易度: 一ツ星 / 二ツ星 / 三ツ星 / おまめ専用
- 形式: <下記のいずれか>

## 問題
問題文。

## 選択肢
形式に応じて記載。

## 正解
正解。

## 解説
不正解時に表示する補足。省略可。

## 根拠
出典と確信度。

## 実装メモ
UI 上の注意や、記述式から候補選択に変えた際の候補など。省略可。
```

## 形式

| 形式 | 内容 | 実装上の型 |
|---|---|---|
| マルバツ | ◯ / × | `tf` |
| 4択 | 選択肢から 1 つ (2〜6 個)。本文を付ける場合は `[語]` で囲むと破線の下線で強調される。記号で答える問題は「選択肢は並べ替えない」と書く | `choice` |
| 並べ替え | 3〜6 個をタップして順に積む | `order` |
| 仕分け | 各カードを 2 つの箱 (例: 誤っている / 正しい) にドラッグして仕分ける。正解数は示さない。「N 個を箱に入れる」形式も可 | `multi` |
| 仕分け＋並べ替え | 各カードを 2 つの箱に仕分け、片方の箱 (例: 死亡した) は上から順番も答える。両方が完全一致で正解 | `pickorder` |
| 穴埋め・組み合わせ | 共通候補を解答欄へドラッグ (使った候補は再利用不可、余りがあってよい)。空欄ごとに候補が違う場合は解答欄をタップして選ぶ | `fill` |

問題文は命令形 (「選べ」「埋めよ」) ではなく丁寧語 (「選んでください」「埋めてください」) で書く。
記述式 (自由入力) は採用しない。空欄は候補選択に置き換え、候補には誤答 (ダミー) を必ず混ぜる。
組み合わせ問題は候補が単一使用なので、正解が行ごとに異なるように作る (同じ候補を 2 行で使う問題は不可)。
